# 维度准备与配置窗口

## 为什么初次进入慢

眼睛原先直接执行跨维度传送。未访问过的竞技场没有入口区块，传送过程中需要生成结构、地形、光照并加载实体；客户端之后还要接收和渲染区块。这不是重置管理器保存或读取整个维度的快照。默认配置下，首次进入也不会触发二次进入结构重置。

现在玩家使用眼睛时，先留在原维度，通过 Minecraft 的区块票据分批请求入口附近的 5×5 区块，每 tick 最多增加两个请求，等 FULL 区块和实体准备好后再执行原有传送。准备期间显示本地化的维度名称及已准备区块数；不调用主线程上会等待完成的 `getChunk` 或 `getChunkFuture` 来强行加载入口。C2ME 仍负责其正常的区块生成与 IO 调度。

- 保持眼睛在手中等待即可；换手中物品、离开原维度、死亡或断线会取消待传送请求。
- 等待时不消耗眼睛、不保存归返点、不提前给予缓降或设置传送冷却；真正开始传送时才执行这些操作。
- 重复使用同一个眼睛不会重复排队或重复消耗。多个玩家前往同一维度时共享准备任务。
- 任务有超时及票据清理；加载失败时提示稍后重试，不因加载失败消耗眼睛。
- 再次进入后的结构回放也显示进度，但重置状态查询接口及原有重置策略不变。
- 这不会消除所有卡顿：大型结构生成、客户端收包/渲染、其他模组的主线程任务仍会耗时。5×5 入口区块不等于预生成整个竞技场、全维度或任意客户端视距。

## 可选预生成

开启 `pregenerate_dimensions` 后，下次进档或启动服务器后，在后台依次准备八个维度的入口区块，不阻塞在创建世界界面等待全部完成；玩家主动传送优先于后台任务。旧存档也可开启，不必新建世界。

默认关闭，避免所有玩家为了不一定访问的维度支付额外的 CPU、内存和磁盘成本。生成结果会随世界保存；准备票据释放后区块可以正常卸载，不承诺永久驻留内存。后台尚未完成时马上进入，仍可能需要等待。此选项和“无人时重置”是不同功能，预生成不回放或重置结构。

## 配置入口与生效时机

在 Forge / NeoForge 的“模组”列表中选中 Cataclysm Dimension，点击“配置”。所有选项均提供简体中文、英文名称与悬停说明，包含生效时机。支持分页、恢复默认、保存与取消。

保留 `config/cataclysm_dimension/cataclysm_dimension.json` 及原有键名，不迁移到另一个 TOML 文件。保存采用临时文件替换，保留未知键；保存失败不会应用本次运行时修改。配置页中的恢复默认需要点击保存才会生效，取消或 Esc 不保存。

这些是服务端规则，不是客户端可覆盖服务器的选项。单人游戏修改本地配置；专用服务器由服主修改服务端配置后重启。连接远程服务器时配置页只读，显示的是本地配置而非远程服务端的值。

| 设置 | 功能 | 生效时机 |
| --- | --- | --- |
| `enable_teleport_eye` | 潜行使用眼睛进入竞技场 | 本地保存后；关闭会取消尚未执行的眼睛传送 |
| `keep_structures_in_original_dimensions` | 同时保留原维度中的灾变结构生成 | 重启游戏/服务器；仅影响新生成区块，完整采用新布局建议新建世界 |
| `random_spread_in_dimension` | 使用随机分布而非固定原点竞技场的放置规则 | 同上；不会移动既有结构 |
| `reset_dimension_if_no_player` | 无人 200 tick 后回放原点附近的结构 | 本地保存后；不删除维度文件，可能加载未访问维度 |
| `slow_fall_when_enter_dimensions` | 进入时给予缓降 | 保存后的下一次传送，不移除已有药水效果 |
| `disable_respawn` | 禁止在竞技场使用床/重生锚 | 重启游戏/服务器并重新进档，无需新建世界；不清除已有重生点，不是禁用 Boss 重生 |
| `consume_teleport_eye` | 非创造玩家传送时消耗一个眼睛 | 保存后的传送开始时 |
| `allow_use_eye_in_dimension` | 允许在竞技场里继续使用眼睛 | 本地保存后 |
| `reset_structure_on_reentry` | 默认关闭；开启后首位玩家再次进入已使用竞技场时回放结构 | 本地保存后；不取消已开始的回放 |
| `enable_return_rift` | 默认开启；主 Boss 死亡后生成归返裂隙，维度无人时自动清理 | 保存后的击杀；不追溯旧击杀，关闭不会立即删除已有裂隙；无人清理不依赖此开关 |
| `reset_structure_requires_boss_kill` | 二次进入重置需要击杀主 Boss 的标记 | 本地保存后；需启用二次进入重置，不改变独立的无人重置选项 |
| `pregenerate_dimensions` | 进档后后台准备入口区块 | 下次进档/启动服务器；无需新建世界 |

生效时机为“本地保存后”的设置也不会撤销已经排队或开始的结构任务、既有实体或已给予的效果。世界生成选项由内置数据包决定，不能通过配置窗口即时重新布局已生成的世界。

## 本地验证记录（2026-10-26）

两版依次测试，启动前等待其他 Minecraft 客户端退出；使用独立临时新世界，不操作用户存档。临时测试驱动不放入发布包。

- NeoForge 1.21.1 / C2ME `0.4.0-alpha.0.123+1.21.1`：真实客户端连接专用服务端，经眼睛使用事件依次进入八个维度；验证目的地未准备好时不消耗眼睛，切换物品取消传送，重复请求不重复消耗，每次成功进入仅消耗一个眼睛。八个维度均成功，后台准备队列也能完成。日志：`/tmp/cataclysm-loading-server-121.log`、`/tmp/cataclysm-loading-client-121.log`。
- Forge 1.20.1 / C2ME Forge `0.2.0-forge.9.9.3`：同样完成八个维度的眼睛传送、取消、重复请求及消耗检查，后台队列完成。日志：`/tmp/cataclysm-loading-server-120.log`、`/tmp/cataclysm-loading-client-120.log`。
- 两版均通过实际配置扩展工厂打开界面，截图核对简体中文和英文，修正小窗口下分页与说明的重叠。1.21.1 另验证修改配置、保存、重新加载后的值保持一致。Forge 的语言切换截图与联机传送分开测试，避免临时 UI 驱动的资源重载干扰连接。
- 1.21.1 新世界在没有玩家进入任何维度时，开启启动预生成后，八个入口任务全部成功完成。日志：`/tmp/cataclysm-loading-startup-server-121.log`。该轮同时复核修正后的配置窗口与保存行为，日志：`/tmp/cataclysm-loading-startup-client-121.log`。

这些不是整合包性能基准，也不是大型竞技场所有区块的完整预生成验收；多人压力、各类第三方传送入口和全部数据包组合未在这轮逐项验证。
