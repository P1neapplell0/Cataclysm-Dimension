# 维度结构重置

两个分支分别面向 Minecraft 1.21.1 / NeoForge 和 1.20.1 / Forge，不可混用构建产物或测试存档。

## 实现

- 参考 P1nero Battle Field1 的分批任务推进方式，每 tick 最多加载或回放两个区块，全服同时推进一个任务。
- 参考 Structure Rewind Watch，从已有 StructureStart 的 NBT 克隆结构布局，逐区块回放；不重新抽取布局，不删除 region、entities、poi，也不操作区块 IO 缓存。
- 回放前用区块票据加载整个目标并等待实体加载完成；完成、失败、停服时释放票据。任务超时 2400 tick，上限 4096 个区块。
- 修正模板锚点、运行期方块后处理、箱子/发射器的重建，并向玩家同步区块；陷入方块的玩家会尝试被移到上方安全位置。
- 模板实体按来源和出生槽位替换；保留玩家、驯养实体和正在骑乘的实体，不清空竞技场里的所有生物或掉落物。
- 这属于结构回放，不是整个维度的方块快照回滚；结构模板不覆盖的玩家建筑不保证清除。

## 兼容接口及配置

- `RESOURCE_KEY_BOOLEAN_MAP`、`RESOURCE_LOCATION_INTEGER_MAP`、`DELAY` 保持公开，键和值类型不变。无人重置仍在开始等待时置布尔值为 true；倒计时从 200 tick 递减到 0，有玩家且无进行中的任务时恢复为 false。
- `reset_dimension_if_no_player` 开启后，无人时延迟回放原点附近的竞技场，不再在启动或运行期删除整个维度文件。
- `reset_structure_on_reentry` 默认关闭，开启后保留二次进入触发及 40 tick 延迟；`reset_structure_requires_boss_kill` 保留击杀主 Boss 后才标记、成功恢复才消费标记的行为。
- 1.20.1 保留 `DimensionTeleportInfo`、`TELEPORT_MAP` 以及原有传送器类。
- 1.20.1 同步归返裂隙的实体注册、眼睛全亮渲染、粒子、主 Boss 判定、出发点保存和归返逻辑；`enable_return_rift` 在两个版本中均默认开启。
- 归返裂隙在自身的服务端实体 tick 中检查维度玩家列表，无人时自行移除，不在全服 tick 中扫描维度或实体。未进入实体 tick 的裂隙需等恢复 tick 后检查；从磁盘加载时若维度无人或已标记结构重置清理，则拦截旧裂隙。不强制加载区块，不依赖再次进入重置、无人重置或裂隙生成开关，还有玩家时不会因无人检查而清理。
- 默认值仅用于缺失配置项和界面恢复默认，已有 JSON 中的显式配置值不覆盖。

## 回归检查

两个版本必须依次验证，前一个服务端完全退出后再启动下一个，使用独立临时目录和存档。

启动游戏测试前先检查是否已有 Minecraft 客户端实例；如有，等待其退出，不并行启动另一个客户端，也不关闭用户的实例。

1. 使用对应 JDK（1.21.1 用 21，1.20.1 用 17）运行 `bash gradlew build`。
2. 启动独立专用服务端，确认 mixin 和实体注册正常；对同一竞技场连续执行两轮结构回放，检查重复请求被拒绝、任务成功回调、busy 状态释放以及没有后处理异常。
3. 客户端开启 `enable_return_rift`，在非灾变维度使用眼睛进入，击杀对应主 Boss；确认裂隙眼睛与维度对应、无法破坏，右键回到原坐标及朝向。
4. 验证缺失归返点时退回主世界出生点、关闭裂隙配置不生成裂隙、小 Boss 不触发，以及重置后旧裂隙不再出现。
5. 验证多人进入不打断正在进行的战斗、关闭二次进入重置、仅击杀后重置、无人倒计时以及跨重启的脏维度记录。

服务端冒烟无法替代客户端渲染、右键交互和多人联机验收。

## 1.7.1 与旧实现的对比

`2ea6fba293a31530d80f1d89c30ce5a16a60d7d6` 与当前实现都通过 `StructureStart.placeInChunk` 恢复结构，不通过删除区块文件进行运行期重置，均不是整个维度的快照恢复。

| 项目 | 2ea6fba | 1.7.1 |
| --- | --- | --- |
| 调度 | 进入后等待 40 tick，在一个 tick 内完成整个结构 | 保留进入延迟，逐 tick 分批加载及回放 |
| 布局 | 直接修改已经使用过的 StructureStart | 从存档 NBT 克隆布局，避免修改原始结构及模板锚点漂移 |
| 实体 | 删除范围内所有 Mob | 等待区块实体加载，按模板出生槽位替换，保护玩家、宠物和坐骑 |
| 方块后处理 | 只调用结构放置 | 补充运行期后处理、容器重建和客户端区块同步 |
| 失败管理 | 捕获同步异常 | 额外提供区块票据释放、超时和任务状态清理 |
| 无人重置配置 | 启动期删除维度文件 | 无人倒计时后回放结构，不接触区块 IO 文件 |

### C2ME 故障定位

2026-10-26 的本地 `run/logs/debug-1.log.gz` 和 `run/logs/2026-10-26-1.log.gz` 记录了 C2ME `0.4.0-alpha.0.123+1.21.1` 的 `MixinChunkNoiseSampler` 注入失败：

```text
Initializing MixinExtras ... version=0.4.1
MIXINEXTRAS:EXPRESSION is not a valid injection point specifier
```

这一错误位于 C2ME 的密度函数/区块生成代码，而不是结构重置任务。此前使用已生成区块的无人服务端冒烟没有覆盖此路径；连接真实客户端请求更多新区块后可以复现。只还原 `restoreStructure` 不能消除这个运行环境错误。

NeoForge 1.21.1 产物现在通过 Jar-in-Jar 内嵌 MixinExtras NeoForge 0.5.3，同时将其用于开发运行环境，让加载器选择不低于 0.5.3 的版本。C2ME 本身不内嵌、不设为必需依赖；开发者可用 `bash gradlew runClient -Pc2meCompatTest=true` 加入本次测试的 C2ME 版本。

Forge 1.20.1 与 NeoForge 的 C2ME 不是同一个构建，不能使用 `9131675` 的 1.21.1 JAR 测试 1.20.1。Forge 测试使用 CurseForge 项目 `concurrent-chunk-management-engine-forge` 的原生 Forge 移植版，而非 Fabric JAR；2026-10-26 核对的当前文件为 `c2meforge-0.2.0-forge.9.9.3-all.jar`（文件 ID `9302662`），其模组元数据要求 Forge 47+、Minecraft `[1.20.1,1.21)`。两版继续分别构建，版本号统一为 1.7.1。

### 客户端回归记录（2026-10-26）

在独立测试目录启动真实客户端连接专用服务端，双方安装对应版本的 C2ME；由临时测试驱动控制真实玩家进入维度，通过玩家的方块破坏路径破坏方块，返回主世界，再进入同一维度，等待正常的维度切换事件触发重置。没有直接调用重置管理器代替这一流程。

抽样限制在玩家水平坐标 ±24 格，位于测试服务端视距内。客户端通过 `ClientChunkCache.hasChunk` 检查区块是否真正加载，而不是使用始终返回 true 的 `ClientLevel.hasChunk`。每次重进后，服务端等待客户端报告所有抽样位置的区块已加载，且客户端抽样位置的非空气方块数不低于服务端恢复原状态的方块数，再进入下一个维度。此检查针对区块加载及抽样方块恢复，不是全结构或客户端每个方块状态的逐项校验。

本轮 PASS 要求每个维度都有破坏后的抽样方块恢复为原状态、所有抽样位置的区块均在客户端加载，不代表全部破坏方块恢复。例如最终测试的 infernos_maw 在 1.21.1 恢复 57/74 个、1.20.1 / Forge `.9.9.3` 恢复 40/70 个；结构包围盒里的自然地形、模板忽略位置与随机放置结果需要和结构方块区分，不能将此测试视为全维度快照回滚验收。

1.20.1 使用 Forge 47.3.0、C2ME Forge `0.2.0-forge.7`，八个维度均完成进出、破坏、重进和客户端加载确认。日志位于本机 `/tmp/cataclysm-player-server-120-final.log` 和 `/tmp/cataclysm-player-client-120-final.log`。

随后从上述 Forge 项目下载 `0.2.0-forge.9.9.3` 替换 `.7`，客户端和服务端均确认加载该版本，再完成八个维度的同一流程，结果为 PASS；两个进程均正常退出。日志位于本机 `/tmp/cataclysm-player-server-120-forge993.log` 和 `/tmp/cataclysm-player-client-120-forge993.log`。这轮在 1.21.1 客户端与服务端完全退出后才启动；启动前还等待其他项目的 Minecraft 客户端退出，没有并行运行两个版本的游戏测试。

1.21.1 使用 NeoForge 21.1.185、C2ME `0.4.0-alpha.0.123+1.21.1`、MixinExtras 0.5.3，八个维度均完成上述严格客户端加载确认，测试结果为 PASS，客户端和服务端均正常退出。日志位于本机 `/tmp/cataclysm-player-server-121-final.log` 和 `/tmp/cataclysm-player-client-121-final.log`。早先的 `fixed-deps` 日志未使用严格区块加载判定，不作为该确认的依据。

| 维度 | 新算法恢复为原状态 | 旧算法恢复为原状态 |
| --- | ---: | ---: |

临时测试驱动不打入发布 JAR；本次不是仅运行无玩家的结构管理器冒烟测试。渲染美术效果、归返裂隙右键及多人战斗并非此次回归的验收范围。
